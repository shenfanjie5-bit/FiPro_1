# PRD 模板（可直接填充）

## 1.1 背景与问题定义

**背景**：追热点、买龙头，但风险偏好较小；需要一个可配置、可解释、可复盘的投研决策应用。

**当前痛点**：
- 数据源分散、口径不一、无法快速形成“今日结论”。
- 热点/事件变化快，需要自动化检索与归因。
- 风险偏好小，必须有硬风控与可回溯逻辑。
- 需要产业链传导视角（原材料/物流/地缘/政策等）。

## 1.2 产品定位（重要）

**产品定位**：投研辅助 + 信号系统（非承诺收益、非自动荐股承诺）。

**输出**：建议动作/推荐指数/关注清单/触发条件/证据链/复盘日志。

**不做**：直接“保证盈利”的承诺、未经授权的自动交易（可留作后续模块）。

## 1.3 目标与非目标

**目标（Goals）**
- G1：在 T+0（当天）生成“标的-建议-理由-风险-触发条件”结构化报告。
- G2：支持“模式/权重/风险偏好”可配置，并可版本化回放。
- G3：支持“重点关注/持仓”标的更深检索与更高频刷新。
- G4：支持产业链图谱联动（事件/商品/航运/区域 -> 影响路径 -> 标的）。
- G5：所有结论可落库、可回忆、可复盘。

**非目标（Non-goals）**
- NG1：不追求端到端“预测涨跌”的黑箱。
- NG2：不在 MVP 阶段做自动下单（可做模拟单/纸上交易）。
- NG3：不做全网无限爬取（先接权威源 + 可控源）。

## 1.4 用户画像与使用场景

**Persona A**：策略开发者（你）- 配模式、调权重、看复盘。

**Persona B**：研究/交易辅助用户 - 看今日建议与重点风险。

**场景**：
- 盘前/盘中：看热点板块 -> 龙头候选 -> 今日是否建议。
- 盘后：复盘今日建议对错、原因、模型引用证据。
- 重点标的：持续追踪关键变量（政策/原材料/运价/地缘/竞品）。

## 1.5 关键用户旅程（User Journey）

**旅程**：配置 -> 生成 -> 盯盘 -> 复盘。

- 用户选择模式（热点龙头低风险）并调整权重（热度/基本面/波动/流动性...）。
- 系统自动拉取数据，构建“事实快照”。
- 触发研究工作流（LLM + 工具）生成结构化结论。
- UI 展示：推荐指数、分价格段位、重点关注信息、产业链图谱路径。
- 用户将标的加入观察/持仓 -> 系统提升检索深度与频率。
- 日终落库：结论、证据、配置版本、工具轨迹 -> 支持回放与评估。

## 1.6 功能需求（按模块拆）

建议用 MoSCoW（Must/Should/Could/Won't）标注优先级。

### A. 策略配置中心（Must）
- 模式管理：创建/编辑/复制/版本化。
- 权重配置：按因子维度设置权重；支持“场景模板”（风险偏好小/中/大）。
- 风控参数：最大回撤阈值、波动率阈值、仓位上限、行业集中度、黑名单规则。
- 版本回放：某天输出必须能绑定到某个配置版本。

### B. 数据面板与事实快照（Must）
- 股票/板块多维数据：行情、技术、基本面、资金、情绪/热度、宏观/大宗/运价。
- 数据口径说明（字段解释、更新时间、缺失情况提示）。
- 重点变量监控：可配置“触发器”（例如：运价指数上行、原材料涨幅、政策事件）。

### C. 产业链图谱（Should，建议尽早做骨架）
- 图谱展示：上游-中游-下游、竞品、替代关系、地区与运输节点。
- 联动：点击“事件/商品/地区/港口/航线”高亮影响路径与受影响标的。
- 图查询：给 LLM 一个可调用接口（query path/exposure）。

### D. 研究工作流（LLM 决策）（Must）
- 今日是否建议（BUY/WATCH/AVOID）。
- 推荐指数（0-100）+ 置信度（0-1）。
- 分价格段位（不同价位区间不同推荐指数 + 条件）。
- 重点关注信息列表（事件类型、方向、紧急程度、监控指标、触发条件）。
- 观点与风险：核心逻辑、潜在反转点、需要验证的数据。
- 输出必须结构化（JSON）并可落库。

### E. 记忆与复盘（Must）
- 决策日志：每天每标的一条结构化记录（含证据与工具轨迹引用）。
- 记忆检索：按标的/主题/时间范围召回。
- 重点标的增强：更深检索、更频繁刷新、生成“变更摘要”。
- 复盘：对比“当时观点 vs 后续事实”，记录“被证伪/被验证”的要点。

### F. 模型管理与可替换（Must）
- 多模型支持：任务级路由（抽取/推理/复核）。
- 影子模式（Shadow）：新模型后台跑不影响前台结果。
- 成本控制：调用预算、缓存、降级策略（主模型不可用时）。

## 1.7 非功能需求（NFR）

- 延迟：盘前生成在可接受时间内（你可定义 SLA）。
- 可用性：数据源失败时可降级（提示缺失，不胡编）。
- 可解释：每条结论要有“证据链/引用的事实快照”。
- 安全：API Key 不落前端；权限隔离；审计日志。
- 成本：可配置每日/每标的调用预算；缓存命中率指标。

## 1.8 指标体系（成功度量）

**业务指标**：
- 覆盖率：每日生成成功率、候选池覆盖度。
- 质量：用户标记“有用/无用”、复盘命中（事件识别是否提前）。

**模型指标**：
- 结构合规率：JSON schema 通过率。
- 事实一致率：引用字段与事实快照一致。
- 幻觉率：无证据断言占比。

**系统指标**：
- 成本/每次运行、延迟、失败率、缓存命中率。

## 1.9 验收标准（Acceptance Criteria）

按模块列“可测试”的验收点（示例）：
- 配置中心：能创建策略版本并在生成记录中绑定版本号。
- 输出：100% 通过 schema 校验；关键字段不缺失。
- 产业链图谱：任一标的可查到至少 N 层上下游并可视化。
- 记忆：对某标的可检索到最近 N 条研究记录并被 LLM 引用。

## 1.10 里程碑（不写时间，只写阶段交付）

- Phase 0：数据快照 + 输出 schema + 落库 + 简单 UI。
- Phase 1：工作流（LLM + 工具）+ 风控门禁 + 复盘。
- Phase 2：产业链图谱联动 + 重点标的增强检索。
- Phase 3：多模型路由 + Shadow + 在线评估与漂移监控。
